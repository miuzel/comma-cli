# AGENTS.md

Guidance for AI coding agents working on this repository. Assumes no prior knowledge of the project.

## Project overview

**comma-cli** (binary name: `comma`, installed as `,`) is a tiny, stateless CLI that translates natural-language intent into a single shell command using an LLM, then optionally executes it after user confirmation. It is a command *generator*, not an agent: one intent → one command → execute → done.

- Language: Rust (edition 2021), single crate, single binary.
- Current version: `0.24.0` (see `Cargo.toml`; the binary reports `env!("CARGO_PKG_VERSION")`).
- Repository: https://github.com/miuzel/comma-cli
- License: MIT.
- Platforms: Linux (x86_64, aarch64), macOS (x86_64, aarch64), Windows (x86_64). On Unix the binary is installed as `,`; on Windows as `comma.exe` (PowerShell reserves `,`).

## Repository layout

The application is a single binary crate split into modules under `src/` (no `lib.rs`). Major areas inside each module are marked with `// ── ... ──` banner comments.

- `src/main.rs` — entry point and dispatch: CLI parsing (only *leading* args are flags; `--` ends flag parsing), `--version`/`--update`/`-h`/`--test`/`--setup`/`-v`/`-vv`, one-shot mode (args joined as intent, trailing `!` = auto-confirm) vs interactive REPL mode, piped stdin → one-shot with line-based confirmation, execute/edit/refine loop (`run_interactive` records prompt inputs for the opt-in history and saves it once after the loop, i.e. for every `q`/`quit`/`exit` exit path). When `load_config()` fails (no usable provider) and stdin is a TTY, the setup wizard runs automatically and config loading is retried afterwards; non-TTY keeps the plain error. `execute()` runs the confirmed command via `$SHELL -c` on Unix (falling back to `/bin/sh` when `$SHELL` is unset); on Windows via `$SHELL -c` when `SHELL` is set (Git Bash/MSYS) and `cmd /C` otherwise — the same SHELL/platform fallback rule `get_shell()` uses (`shell_command()` in context.rs), so execution matches the shell the model generated for. Shell-integration eval mode: when `COMMA_EVAL_FILE` is set (non-empty), `execute()` instead appends the comment-stripped command to that file (one per line) and returns — a wrapper shell function (see README § Shell integration) evals the file in the user's *current* shell, because a child process can never change the parent shell's cwd/environment. In child-process mode a bare `cd` (`is_bare_cd`) prints a note pointing at the wrapper. `execute(cmd, capture) -> Option<ExecOutcome { code, output }>`: `None` in eval mode (nothing ran here, so no exit code and no auto-refine); with `capture == false` it uses `.status()` (streaming stdio, empty output) and with `capture == true` it captures stdout/stderr via `.output()` (stdin still inherited), echoes the captured bytes and returns the combined output. Auto-refine (REPL only, `auto_refine` config, default on): a non-zero exit code — including a signal death where `code()` is `None` — builds a refine turn from the failed command, the exit code and a sanitized/truncated (2000 chars) output summary, with real `$HOME`/user/hostname masked back to `{{HOME}}`/`{{USER}}`/`{{HOSTNAME}}` *before* truncation (`mask_placeholders` in context.rs); the refined command is printed, never auto-executed. `/refine TEXT` (alias `/r`) at the main prompt refines directly instead of going through `x` → `r`.
- `src/ui.rs` — terminal UI: rustyline `FileHelper` (filename Tab-completion), candidate selector (`|||` separated alternatives), spinner, print helpers (`print_info`/`print_error`/`print_debug`/`print_cmd`), confirm/edit/refine prompts (crossterm raw mode, `std::io::IsTerminal` checks, line-based fallbacks for piped stdin), char-boundary-safe `truncate`, clipboard copy. Raw-mode key loops act only on `KeyEventKind::Press` — Windows also reports Release/Repeat events, which must be ignored (a buffered Enter release would otherwise execute without a keypress); on Unix only Press is reported, so the filter is a no-op there.
- `src/config.rs` — config loading: legacy single-model format and multi-provider `providers`/`models` format, `COMMA_*` env overrides, API-style auto-detection, `home_dir`, `full_prompt` (explicit system-prompt override, see prompt.rs), runtime-file path resolution (`platform_path` → `xdg_or_legacy`/`exe_dir`/`history_path`).
- `src/setup.rs` — `, --setup` interactive configuration wizard (also auto-started on TTY when no provider is configured): manage LLM providers (add/edit/delete/reorder — `models` array order IS the fallback order), pick the web-search backend, and toggle the opt-in REPL history and the auto-refine behaviour. Edits happen in memory; saving merges into the existing JSON (unknown keys preserved, legacy single-model keys upgraded to `providers`+`models`), first copies the old file to `config.json.YYYYMMDD-HHMMSS.bak` (UTC, hand-rolled civil-from-days, no date crate), then writes atomically (temp file + rename). Because the merge preserves the existing object, every managed key must be written explicitly (`entries_to_json` always writes `search`-or-removes and `history`; the wizard writes `auto_refine` itself) or the user's choice is silently dropped. Menus reuse the crossterm raw-mode pattern from `select_command`; field names shown are the literal config keys and stay untranslated.
- `src/context.rs` — system context gathering (distro, kernel, arch, shell, CWD, user-installed packages) and privacy placeholders (`{{USER}}`, `{{HOSTNAME}}`, `{{HOME}}`) — collected locally, substituted into LLM output only after the response. `get_shell()` reports `COMMA_EVAL_SHELL` when set and non-empty (the eval wrapper declares the dialect the model should generate for — e.g. `powershell`), then `$SHELL` when set (Git Bash/MSYS users on Windows). On Windows without either, it falls back to `cmd.exe`, but it detects an interactive PowerShell parent by checking for the `PSModulePath` environment variable and reports `powershell` in that case. Unix falls back to `/bin/sh`.
- `src/prompt.rs` — system prompt loading. The default template is the compiled-in `DEFAULT_PROMPT`, so upgrades always take effect. Use `, --default-prompt` to view it. Experts can override via the `full_prompt` config key (total override) or append rules with `additional_prompt.md`. A legacy `~/.config/comma/prompt.md` whose content differs from `DEFAULT_PROMPT` is still honored as a full override. `prefer` tool-preference formatting. The `#SEARCH:` rules (`SEARCH_SECTION`) are appended at runtime when `search.provider` is not `off`, so users with a custom prompt get them without editing their file.
- `src/llm.rs` — LLM clients: OpenAI-compatible (`/v1/chat/completions`), OpenAI Responses API (`/v1/responses`) and Anthropic (`/v1/messages`, optional `reasoning` thinking budget), blocking `ureq` with rustls; ordered fallback and per-model retries in `call_llm_with_retry` (which also re-labels the passed-in spinner per fallback attempt).
- `src/cache.rs` — response cache (`cache_path()` resolves `~/.cache/comma/cache.json` (`%APPDATA%\comma\cache.json` on Windows) first, then exe-adjacent `,.cache.json`, then legacy `~/.local/bin/,.cache.json`; oldest-entry eviction, atomic save only when dirty, parent dir auto-created; entries cached only after the user executes the command; checked across ALL configured model entries in fallback order before any API call; `cache_size: 0` disables caching entirely).
- `src/history.rs` — opt-in REPL input history (`"history": true` in the config, off by default): `config::history_path()` resolves `$XDG_STATE_HOME/comma/history` (default `~/.local/state/comma/history`; `%APPDATA%\comma\history` on Windows) with deliberately no exe-adjacent/legacy fallback. `load_if_enabled`/`save_if_enabled` are the only entry points used by the REPL; while the key is false/absent they never touch the disk, so no file is ever created. The file is one entry per line, capped at the newest `MAX_HISTORY` (1000), rewritten atomically on exit (`q`/`quit`/`exit` → `main.rs::run_interactive`) with 0600 permissions, and read back into the prompt editor at startup so `↑` recalls previous sessions. A missing/empty/non-UTF-8/truncated file loads as empty history (never panics); read-only FS or missing HOME degrade silently. Only prompt inputs are recorded — the `e`/`r` edit/refine text `ui::edit_or_execute` adds to the editor stays in memory and is never persisted.
- `src/update.rs` — self-update (`--update`) from GitHub releases, with archive verification against the release's `sha256sums.txt` and cross-device/locked-exe handling. Both manual `--update` and the periodic `check_and_notify` show the release changelog and ask for consent BEFORE touching the binary (`install_version` is the post-consent part). When an auto-update offer is declined, the user is asked whether to disable future checks (Enter = keep; `prompt_confirm_default_no`), and `y` persists `auto_update: false` via `write_auto_update_flag` in config.rs. Non-TTY (piped) runs never prompt — the old one-line notice only.
- `src/protocol.rs` — `#CHECK:` (tool availability probe), `#EXPLORE:` (run a help command once and learn from output) and `#SEARCH:` (web search, results fed back) protocol handling, chained in `process_response`.
- `src/search.rs` — web search backends for `#SEARCH:`: DuckDuckGo (default, no key — scrapes the lite HTML endpoint; automatically falls back to Mojeek when DDG rate-limits), Mojeek (no key, scraping-friendly), Brave and Tavily (need `search.api_key`), SearXNG (needs `search.base_url`); tolerant regex-free HTML/JSON parsing, no extra dependencies. Richer per-result content comes from backend-native features only (no client-side page fetching): Tavily requests `search_depth: "advanced"` + `include_raw_content` (raw_content is only populated on the advanced depth; may still be null), Brave uses the LLM Context endpoint (`/res/v1/llm/context` — pre-extracted page content in `grounding.generic[].snippets` as plain strings, included in every Search plan); both land in `SearchHit.page_text` truncated to 3000 chars and are rendered by `format_hits`. Tavily's POST goes through `post_json`, which prefers an external `curl` — Tavily serves a degraded Google-grounding pipeline (opaque `/goto?url=` redirect URLs, no raw_content, occasionally mangled queries) to rustls clients, same TLS-fingerprint issue as the scraping backends; the JSON body is piped via stdin so the API key never appears in argv.
- `src/danger.rs` — danger detection: `DANGER_PATTERNS` substring list (whitespace-normalized) plus exact-token pipe-to-shell matching (`curl x | sh` flags, `| shuf` does not), red ⚠ warning.
- `src/i18n.rs` — UI language selection: `config.lang` > `COMMA_LANG` > `LANG`/`LC_ALL` > `"en"`, with `normalize_lang` mapping locale variants (`fr_FR`, `pt-BR`, ...) to a supported code. UI strings go through the `t!` macro (rust-i18n, embedded at compile time via `i18n!("locales", fallback = "en")` in main.rs).
- `locales/` — one `<lang>.toml` per UI language (en, zh, ja, ko, fr, de, es, pt, ru); every file must contain the same keys as `en.toml`. Placeholders are rust-i18n v3 named syntax `%{name}` — `{}` is NOT substituted (this was a real bug in en/ja); match each `t!` call site's argument names. `run_tests` checks placeholder substitution for every locale.
- `src/tests.rs` — `run_tests`, the built-in self-test suite (see Testing below).
- `Cargo.toml` — dependencies: `ureq` (rustls), `serde`, `serde_json`, `sha2` (update checksums), `crossterm`, `rustyline`, `rust-i18n`. TTY detection uses `std::io::IsTerminal` (no `atty` dependency). Release profile: `strip = true`, `opt-level = "z"`, `lto = true`, `panic = "abort"`, `codegen-units = 1` (size-optimized ~2.5MB binary — keep it that way).
- `config.json` — default config template (on Linux/macOS installed to `~/.config/comma/config.json`, honoring `$XDG_CONFIG_HOME`; on Windows to `%APPDATA%\comma\config.json`). `config_path()` in config.rs resolves default-first with exe-adjacent (portable) and legacy `~/.local/bin` paths as fallback for existing installs.
- `build.sh` — builds with cargo and installs to `~/.local/bin` (see below); installs only `config.json` (if missing), not `prompt.md`.
- `install.sh` — end-user installer: downloads the latest GitHub release archive for the detected platform and verifies it against `sha256sums.txt` when available; installs only `config.json` (if missing), and points users without an API key at `, --setup`.
- `uninstall.sh` — removes only the binary (`,`, `,.old`), the response cache (`cache.json`), and the self-update temp dir. User-defined files (`config.json`, `prompt.md`, `additional_prompt.md`, in XDG/legacy/Windows paths) and the opt-in REPL history (`$XDG_STATE_HOME/comma/history`, `%APPDATA%\comma\history`) are kept and listed at the end.
- `.github/workflows/release.yml` — release pipeline (see Deployment).
- `README.md` / `README.zh-CN.md` — user documentation (English / Chinese). Keep both in sync when changing user-visible behavior.

## Build and test commands

```bash
cargo build            # debug build
cargo build --release  # release build (binary: target/release/comma)
./build.sh             # release build + install to ~/.local/bin/, (also copies
                       # config.json → ~/.config/comma/ if missing)
```

There is no `cargo test` suite and no CI check workflow — do not assume one exists.

## Testing instructions

Testing is done via a built-in self-test flag compiled into the binary:

```bash
cargo run -- --test          # or: ./target/release/comma --test
```

`run_tests()` in `src/tests.rs` runs ~390 ad-hoc assertions (placeholder substitution, privacy leak checks on gathered context, empty-HOME guard, `#CHECK:`/`#EXPLORE:`/`#SEARCH:` parsing, DDG lite HTML parsing and redirect unwrapping, candidate parsing, char-boundary-safe `truncate`, `is_dangerous` pattern and pipe-to-shell matching, retry constants, `COMMA_EVAL_FILE` eval-file append, the `execute()` outcome contract (exit code, capture mode, `None` in eval mode), the auto-refine trigger/output-cap/masking rules, `mask_placeholders` reverse mapping, the `/refine` prompt parser, the `auto_refine` config key, history path resolution/disabled-no-write/corrupt-file/0600/cap, `COMMA_EVAL_SHELL` override in `get_shell`, `is_bare_cd` first-token detection, `%{name}` substitution for every embedded locale) and exits non-zero on failure. When you change parsing or privacy-related logic, add matching checks to `run_tests()` and make sure `--test` passes. Manual smoke test (requires a configured API key): `, list files larger than 1G`.

## Code style guidelines

- Keep the module structure; new code goes in the module it belongs to (see Repository layout). Split a new module only when a change genuinely demands it.
- Match the existing style: `// ── Section ──` banner comments separating major areas, short doc comments on non-obvious functions, plain `String`/`Result<_, String>` error handling (no `anyhow`/`thiserror`).
- Blocking, synchronous code throughout (ureq blocking agent); no async runtime — do not add tokio.
- Keep the dependency list minimal and the binary small; check `Cargo.toml` before assuming any crate is available.
- Terminal output goes through the existing helpers (`print_info`, `print_error`, `print_debug`, `print_cmd`) with crossterm colors; interactive input uses crossterm raw mode, with `std::io::IsTerminal` checks and line-based fallbacks for piped stdin.
- Comments and documentation are written in English (user docs also have a Chinese translation, `README.zh-CN.md`).

## Configuration and runtime data

- Config resolution priority: `COMMA_*` env vars (`COMMA_BASE_URL`, `COMMA_API_KEY`, `COMMA_MODEL`, `COMMA_API_STYLE`) → config file (`~/.config/comma/config.json` on Linux/macOS, `%APPDATA%\comma\config.json` on Windows → exe-adjacent `,.config.json` → legacy `~/.local/bin/,.config.json`) → `~/.claude/settings.json` env section (legacy path only) → built-in defaults. API style is auto-detected from URL (`anthropic` in URL → Anthropic Messages API, `responses` in URL → OpenAI Responses API, otherwise OpenAI chat completions).
- `COMMA_EVAL_FILE` is a runtime integration variable (not config): when set and non-empty, `execute()` in `src/main.rs` appends each confirmed command to that file instead of spawning a shell, and the shell-integration wrapper function evals the file in the user's current shell (rationale: a child process cannot change the parent shell's cwd/env).
- `COMMA_EVAL_SHELL` is a runtime integration variable (not config): when set and non-empty, `get_shell()` in `src/context.rs` reports it as the shell in the system context, so the eval wrapper can declare the dialect the model should generate (the PowerShell wrapper sets it to `powershell`; bash/zsh rely on `$SHELL`, and cmd.exe is already the SHELL-less Windows default).
- The multi-provider `providers` + `models` format in the config enables ordered fallback with per-model `retries`. In this format `COMMA_MODEL` overrides only the primary (first) entry's model.
- `cache_size` sets the response-cache capacity; `cache_size: 0` disables the cache entirely (nothing read back or written).
- `history` (bool, **default false**) opts into persisting interactive REPL inputs to `$XDG_STATE_HOME/comma/history` (`%APPDATA%\comma\history` on Windows, see `history_path()` in config.rs); owner-only 0600, newest 1000 entries, written once on REPL exit and never sent to the API. While false/absent nothing is read or written, so no history file is created. `, --setup` can toggle it.
- `auto_refine` (default `true`) enables the REPL's automatic refine after a command exits non-zero; `false` disables it and restores streaming `.status()` execution (no output capture). Toggle it in `, --setup` too.
- `reasoning` (Anthropic only) sets the thinking budget in tokens; `max_tokens` is raised accordingly so values ≥ 1024 work.
- The `search` object configures the `#SEARCH:` web-search backend: `provider` (`off` **by default** — keyless scraping triggers aggressive anti-bot measures, so the model is only told it can search when the user explicitly picks a backend; `brave`/`tavily` need `api_key`; `searxng` needs `base_url`; `duckduckgo`/`mojeek` are keyless scraping, DDG falls back to Mojeek), `max_results` (default 5, clamped to 1–10). Scraping backends fetch via an external `curl` when available (its TLS fingerprint passes bot checks that reject rustls clients); query spaces are encoded as `+`, not `%20` (the latter trips Mojeek's ALTCHA). `#SEARCH:` does NOT prompt for confirmation (read-only request, model-generated query) and is limited to ONE live search per intent (repeats get a text nudge, not another search); `#EXPLORE:` still prompts. Search failures and empty results are fed back to the model as context instead of aborting, so it can still answer from its own knowledge.
- Runtime files are resolved per-file, first match wins: platform default (`config.json`/`additional_prompt.md` under `$XDG_CONFIG_HOME/comma/` resp. `~/.config/comma/`, `cache.json` under `$XDG_CACHE_HOME/comma/` resp. `~/.cache/comma/`; on Windows all under `%APPDATA%\comma\`) → next to the executable (`,.config.json` / `,.additional_prompt.md` / `,.cache.json`, for portable installs) → legacy `~/.local/bin/` → if none exists, the platform default (where new writes go). Resolution lives in `xdg_or_legacy()` / `exe_dir()` in config.rs. The opt-in REPL history is the exception: `history_path()` resolves only `$XDG_STATE_HOME/comma/history` (`~/.local/state/comma/history`, `%APPDATA%\comma\history` on Windows) — no exe-adjacent or legacy fallback, and no file at all unless `history: true`.
- The `, --setup` wizard (src/setup.rs) manages LLM providers (order = fallback order), the search backend, and the REPL-history / auto-refine toggles, backing up the existing config to a timestamped `.bak` before saving; it starts automatically on TTY when no provider is configured.

## Security considerations

- **Privacy by design**: username, hostname, and home path must never be sent to the LLM API. The system context sanitizes CWD to `{{HOME}}`/`{{USER}}`, and the model is instructed to emit `{{USER}}`/`{{HOSTNAME}}`/`{{HOME}}` placeholders that are substituted locally after the response. On interactive refine, the *raw* (pre-substitution) reply is what goes back to the API as conversation history, so real paths never leak. Auto-refine follows the same rule for command output: `mask_placeholders` (context.rs) turns real home path/username/hostname back into `{{HOME}}`/`{{USER}}`/`{{HOSTNAME}}` — before truncation — and `run_tests` asserts the serialized refine turns contain none of the real values. Preserve this invariant — `run_tests` has explicit "context does not leak ..." checks.
- Config files contain API keys (`auth_token`); never commit real keys, log them, or print them in verbose/debug output.
- Generated commands are shown for confirmation before execution; dangerous patterns are flagged via `DANGER_PATTERNS` and pipe-to-shell matching. Piped stdin is no exception: `echo intent | ,` asks for a `y` line on stdin before executing, and only `echo intent | , !` (auto-confirm) skips it. The `!` auto-confirm flag and `--update` self-replacement exist by design — be careful not to weaken the confirmation flow silently.
- `#EXPLORE:` commands requested by the model are executed via the same SHELL-aware rule as `execute()` (`shell_command()` in context.rs) after user confirmation (a single probe asks too) unless auto-confirm; output is truncated to 4096 chars before being fed back to the LLM.
- Self-update (`--update`) verifies the downloaded archive against the release's `sha256sums.txt` before replacing the binary.

## Deployment process

Releases are fully automated via `.github/workflows/release.yml`:

1. Push a git tag matching `v*` (after bumping `version` in `Cargo.toml`).
2. GitHub Actions builds release binaries for 5 targets: `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu` (via `cross`), `x86_64-apple-darwin`, `aarch64-apple-darwin`, `x86_64-pc-windows-msvc`.
3. Each is packaged (`comma-<os>-<arch>.tar.gz`, or `.zip` for Windows); a `sha256sums.txt` covering all archives is generated and published to the GitHub release by `softprops/action-gh-release`, together with `install.sh`.
4. **Write real release notes.** The workflow's `generate_release_notes: true` only emits a `**Full Changelog**: ...compare...` link (we release from direct main commits, no PRs to list), and since v0.24.0 the update flow (`--update` and the auto-update check) shows the release body to users before they consent to upgrading — a bare compare link is not acceptable. After CI publishes the release, set notes that lead with 1–3 lines of what the release actually does (feature name + user-visible effect), keeping the compare link at the bottom:
   `gh release edit vX.Y.Z --repo miuzel/comma-cli --notes-file <file>` (write the file first; avoid inline `--notes` quoting pitfalls). Backfill older releases the same way when they lack notes.

End users install/update via `install.sh` or the built-in `, --update`, both of which pull from GitHub releases and verify the archive against `sha256sums.txt` — so archive names in the workflow, `install.sh`, and `do_update()` in `src/update.rs` must stay consistent.

There is also a Homebrew tap at `miuzel/homebrew-tap` (install: `brew install miuzel/tap/comma-cli`). Its `Formula/comma-cli.rb` is **not** updated by the release workflow — after each release, bump `version`, update the four archive URLs, and copy the new hashes from the release's `sha256sums.txt`, then push. The formula installs the binary as `,` (alias `comma`) plus a `comma-setup` helper that interactively writes `~/.config/comma/config.json` (skipping the prompts still leaves a default config for manual editing) — the setup prompt cannot live in `post_install`, because Homebrew points HOME at a temporary build dir during install hooks and user lookups are unreliable there.

**After pushing a release tag, wait ~10 minutes before testing `, --update` or `install.sh`.** The `releases/latest/download/` redirect lags behind on GitHub's CDN: right after a release it can serve the *previous* release's `sha256sums.txt` together with the *new* archive, causing a spurious checksum mismatch (the abort is the safety check working, not a broken release). Pin-tag URLs (`releases/download/vX.Y.Z/...`) are not affected.
